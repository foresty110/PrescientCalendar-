# 모바일 반응형을 보류하고 데스크탑 웹 단일 타겟으로 우선 출시

- 날짜: 2026-05-13
- 상태: 채택
- 관련 기능: FEATURES.md I.5(제거됨), I.4(데스크탑만으로 축소)

## 맥락

원래 비기능 요구사항에 "375px(iPhone SE)에서 사용 가능"이 있었고 FEATURES I.5("모바일 반응형")가 별도 항목으로 있었다. Playwright e2e도 데스크탑·모바일 두 프로젝트로 설정.

다만 다음 이유로 우선순위 재평가:

- **사용 환경**: 캘린더 + LLM 채팅은 입력 타이핑 양이 많아 1차 사용자(개발자 본인) 거의 데스크탑에서만 씀
- **구현 비용**: 캘린더 그리드·채팅 사이드바·회고 모달 모두 다른 반응형 레이아웃 필요. 디자인 의사결정·QA 비용 모두 ↑
- **포트폴리오 임팩트**: 데스크탑에서만 완성도 높은 것이, 양쪽 어정쩡한 것보다 보여주기 좋음
- **부활 비용 낮음**: Tailwind 클래스(`sm:`/`md:`/`lg:`)를 dormant로 두면 추후 추가가 점진적으로 가능

## 고려한 대안

- **A) 원안대로 양쪽 다 지원** — 일정 ~3일 추가, 모바일에서 회고 모달·캘린더 UX 별도 설계 필요
- **B) 모바일 전용으로 재설계** — 1차 사용자 환경과 불일치, 거부
- **C) 데스크탑 단일, 모바일 보류** *(채택)* — 핵심 가치 집중, 부활 경로 보존

## 결정

C 채택.

- FEATURES I.5 제거, I.4의 "모바일 뷰포트" 문구도 제거
- `docs/requirements.md`의 비기능 "모바일 375px" → "데스크탑 우선 1024px+" + "MVP 범위 외" 절에 모바일 항목 추가
- `docs/development.md` UI 섹션을 "Tailwind, 데스크탑 우선" 로 변경
- Tailwind 반응형 클래스·`playwright.config.ts`의 mobile project는 **dormant로 유지** — 추후 부활 시 즉시 활성

## 결과

**좋은 점**:
- 데스크탑 한 환경에 집중해 완성도 ↑
- 캘린더·채팅·회고 모달의 디자인·QA 결정 단순화
- README에 "scope 의식 결정" 흔적 (ADR 자체가 자산)

**트레이드오프 / 향후 위험**:
- 모바일 사용자는 화면 깨짐 가능 — landing 페이지에 "데스크탑 우선" 안내가 필요할 수도 있음 (별도 작업)
- 새로 추가하는 컴포넌트가 모바일 클래스를 안 붙이는 경향이 생길 수 있음 — 부활 시 일관성 보정 비용

**재활성 절차** (추후 부활 시):
1. 이 ADR의 상태를 `채택 → 변경됨(→ 새 ADR)`로 갱신
2. `docs/requirements.md`의 비기능 "데스크탑 우선" → "모바일 + 데스크탑" 으로 환원, "MVP 범위 외"에서 모바일 항목 제거
3. `docs/development.md` UI 섹션을 "모바일 우선"으로 환원
4. FEATURES.md에 I.5 재추가, I.4에 "모바일 뷰포트" 추가
5. 각 컴포넌트의 반응형 클래스 점검·보강
6. Playwright e2e에 mobile project 재활성 (현재는 dormant 상태로 남김)
