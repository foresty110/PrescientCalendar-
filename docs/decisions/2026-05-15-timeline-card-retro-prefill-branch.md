# 타임라인 카드 클릭 → 회고 흐름 분기를 채팅 prefill 문구 차이로만 구현

- 날짜: 2026-05-15
- 상태: 채택
- 관련 기능: FEATURES.md 5.3 (타임라인 Phase 3 첫 단추)

## 맥락

Phase 2까지 타임라인의 카드 다섯 가지 상태(예정·진행중·회고 필요·완료·스킵) 모두 동일한 prefill 문구를 채팅 입력란에 넣었다. 그래서 회고가 필요한 카드를 클릭해도 사용자가 입력란의 문구를 직접 회고 톤으로 고쳐 써야 회고 흐름으로 들어갈 수 있었다. Phase 3의 첫 단추로 "완료 일정 클릭 → 회고 흐름 분기"를 어떤 방식으로 구현할지 결정이 필요했다.

## 고려한 대안

- **A 옵션 — 채팅 컨텍스트(ChatContext)에 `mode` 필드 추가** 시스템 프롬프트에 명시 주입: 라우팅 정확도는 가장 높지만, FEATURES.md 5.3의 마지막 항목 "시스템 프롬프트에 컨텍스트 일정 메타 주입"과 영역이 정확히 겹쳐 같은 PR로 묶지 않으면 두 번 다듬게 된다. 변경 범위도 Chat/AppShell/시스템 프롬프트까지 넓어진다.
- **B 옵션 — 카드 status별로 prefill 문구만 분기** 채팅 컨텍스트 모양은 그대로 두고, LLM이 `retrospect.md` 모드 A의 자연어 트리거("어땠어"/"회고")로 회고 흐름에 라우팅된다고 위탁. 변경은 AppShell 한 파일에 그친다.
- **C 옵션 — 카드 클릭 시 회고 입력 모달 표시** Phase 1에서 이미 도입한 `RetrospectModal`을 다시 띄움. 채팅 통합 UX 방향과 어긋나고 Phase 3 목표(채팅 안에서 일관된 흐름)와 맞지 않는다.

## 결정

B 채택. 이유: 첫 단추는 가벼운 변경으로 가치를 확인한 뒤 명시 주입은 Phase 3 마지막 항목과 묶어 한 번에 다듬는 편이 응집도가 높다. 사용자가 채팅 입력란을 직접 보고 보내는 흐름이므로, 분기가 어긋나도 사용자가 즉시 고쳐 회복 가능하다.

## 결과

- **좋아진 점**: 변경 범위 한 파일(`src/app/(app)/app/AppShell.tsx`, +15/-1). 회고 안 된 카드 클릭 시 `"어땠어? 회고할게"`, 회고된 카드 클릭 시 `"회고 기록 정리해줘"`로 prefill되어 한 클릭 안에 회고 흐름이 시작된다.
- **트레이드오프 / 향후 위험**: LLM이 `retrospect.md` 모드 A의 자연어 트리거로 분기한다고 위탁한다. 위탁이 깨지면(예: 모델 업데이트 후 문구 인식 변화) 사용자가 직접 입력란을 수정해야 한다. 5.3 마지막 단추에서 `ChatContext.mode` 명시 주입을 추가하면 이 위탁은 안전망이 두 겹이 되며 자연 해소된다.
