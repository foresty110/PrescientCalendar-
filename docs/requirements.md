# Requirements

## 1. 사용자 계정 (로그인)
**목적**: 사용자별 데이터 격리, 추후 Google Calendar 연동 경로 확보.

**범위(In Scope)**:
- Google OAuth 로그인 / 로그아웃
- 보호 라우트 접근 차단 (미들웨어)
- 모든 도메인 쿼리에 userId 필터 + IDOR 방어

**범위 밖(Out of Scope)**:
- 비밀번호 로그인, 이메일 매직링크
- 다른 OAuth 제공자
- 사용자 프로필 편집 UI (이름·이미지는 Google 그대로 사용)

**완료 기준**:
- [ ] `/signin`에서 Google 로그인 → DB에 User/Account/Session row 생성
- [ ] 미로그인 상태로 `/` 접근 시 `/signin`으로 리다이렉트
- [ ] 다른 사용자의 ScheduledRun ID를 직접 호출하면 403

## 2. 대화형 일정 잡기
**목적**: 자연어 한 줄로 일정을 만들고, 수정·삭제까지 대화로 가능.

**범위(In Scope)**:
- 단발 일정 ("내일 3시에 운동 1시간")
- 반복 일정 ("매주 화요일 9시 회의")
- 기존 일정 수정·삭제 (대화로)
- 모호한 입력 시 LLM이 되묻기
- 시간 충돌 경고

**범위 밖(Out of Scope, MVP)**:
- 외부 캘린더 연동 (단, Google OAuth 토큰은 받아둠)
- 다국어 (한국어만)
- 일정에 위치·참석자·알림 등 부가 정보

**완료 기준**:
- [ ] "내일 오후 3시 1시간 운동" → Event + ScheduledRun 생성, 캘린더 표시
- [ ] "그거 4시로 옮겨줘" → 마지막 일정 수정
- [ ] "나중에 운동" 같은 모호 입력은 시각 확정 질문
- [ ] 같은 시간 일정 있으면 경고 + 사용자 확인 후 진행

## 3. 회고 (대화형 우선)
**목적**: 일정 실행 여부 + 설정·실제 시각 차이를 채팅으로 자연스럽게 기록. UI 모달은 보조.

**범위(In Scope)**:
- 단건 회고: "아까 운동 30분 늦게 시작했어"
- 일괄 회고: "어제 회고 같이 하자" → assistant가 순차 질의
- 상태 자동 추론 (완료/스킵/지연) + 사용자 확인
- 캘린더 셀 클릭 → 빠른 입력 모달
- 회고 통계 채팅 질의 ("이번 주 운동 실행률 어때?")

**범위 밖**:
- 사진·메모 첨부
- 회고 알림 푸시

**완료 기준**:
- [ ] 채팅·UI 둘 다 동일 `record_actual_run` 호출
- [ ] LLM이 시각·소요·상태 추론 후 사용자 확인 메시지 출력
- [ ] 회고 통계 질의 시 `query_user_pattern` 호출되어 응답

## 4. 실현 가능성 예측
**목적**: 새 일정의 달성 가능성을 0~100 점수로 보여줘 사용자가 계획 시 참고.

**범위(In Scope)**:
- 일정 생성 직후 자동 산출
- 점수 + 근거를 캘린더 셀 색상·뱃지로 표시
- 채팅 질의 가능 ("이거 가능할까?")
- 데이터 부족 시 회색 처리

**범위 밖**:
- 점수 알고리즘을 학습하는 인프라
- 시간대별 fine-grained 예측

**완료 기준**:
- [ ] 일정 생성 후 `ScheduledRun.feasibilityScore` 채워짐
- [ ] 캘린더 셀에 점수에 따라 색상/뱃지
- [ ] 같은 시간대 ±1h ActualRun 5건 미만이면 "데이터 부족" 회색

## 5. 다음 주 예측 캘린더
**목적**: 사용자의 회고 패턴 + 반복 일정에서 다음 주 일정을 자동 제안.

**범위(In Scope)**:
- 결정론 단계: recurrence 있는 Event는 그대로 복사
- LLM 단계: 회고 패턴에서 새 제안 발굴
- 별도 뷰 `/next-week` — 일반/AI 제안 구분
- 수락 시 실제 ScheduledRun 생성

**범위 밖**:
- 자동 푸시 알림
- 매일 단위 예측

**완료 기준**:
- [ ] 반복 일정 fixture → 다음 주에 동일 복사 확인
- [ ] LLM 제안은 회색 톤 + "AI 제안" 뱃지
- [ ] 수락 버튼으로 ScheduledRun 생성

## 비기능 요구사항

- **응답 지연**: 채팅 첫 토큰 ≤ 2초 (Anthropic streaming + 프롬프트 캐싱)
- **시간대**: DB는 UTC, 입출력은 KST (`date-fns-tz`)
- **프라이버시**: 캘린더는 개인 정보 — 시크릿/PII는 로그·에러 응답에 노출 금지
- **모바일**: 375px(iPhone SE)에서 사용 가능
- **데이터 격리**: 모든 도메인 쿼리에 userId 필터 + IDOR 방어
