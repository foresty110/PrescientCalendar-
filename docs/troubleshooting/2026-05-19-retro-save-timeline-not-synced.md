# 캘린더 셀에서 회고를 저장하면 캘린더는 갱신되는데 타임라인은 옛 값으로 남는다

- 날짜: 2026-05-19
- 영향 범위: 로컬·prod 공통 — `/app` 대시보드 UI
- 관련 기능: FEATURES.md 3.4 (캘린더 chip 클릭 회고 모달), 5.1 (일정 목록 타임라인)

## 무슨 일이 있었나

`/app` 대시보드는 위에 월 캘린더, 아래에 "일정 목록" 타임라인이 함께 있고
두 영역은 같은 일정 데이터(`/api/events`)를 보여준다. 캘린더 날짜 셀의 일정
chip 을 클릭하면 회고 입력 모달이 떠서 실제 시작 시각·소요·상태를 기록한다.

평소 정상 동작이라면, 회고를 저장했을 때 캘린더 chip 색이 "회고 필요(amber)"
에서 "회고됨(emerald)" 으로 바뀌고, 같은 일정을 그리는 아래 타임라인 카드의
상태 배지도 함께 바뀌어야 한다.

이번 증상: 회고를 저장하면 캘린더 셀은 새 값으로 바뀌는데, 아래 타임라인은
저장 전 상태를 그대로 유지했다. 페이지를 새로고침해야만 타임라인이 맞춰졌다.

## 왜 풀기 까다로웠나

증상만 보면 "타임라인이 갱신 신호를 못 받는다" 로 보이지만, 타임라인은
채팅으로 일정을 바꿀 때는 정상 갱신된다. 즉 타임라인 컴포넌트 자체는
멀쩡하고 문제는 "회고 저장" 이라는 특정 경로에만 있었다 — 어느 컴포넌트가
고장났나가 아니라 어느 경로의 배선이 다른가를 봐야 했다.

## 원인

대시보드(`AppShell`)에는 "데이터가 바뀌었으니 다시 불러와라" 는 전역 신호
`refreshKey` 가 있고, 캘린더와 타임라인 둘 다 이 값을 구독해 바뀌면
`/api/events` 를 재조회한다. 채팅 응답 완료·테스트 데이터 시드는 이 신호를
올려서 양쪽이 함께 갱신된다.

그런데 회고 모달의 저장 성공 콜백만 이 전역 신호를 쓰지 않고, 캘린더
컴포넌트 내부의 로컬 state(`localRefresh`)를 올리고 있었다. `localRefresh`
는 캘린더 안에만 존재해 타임라인이 볼 수 없다. 그래서 회고 저장 시 캘린더만
재조회되고 타임라인은 신호를 받지 못한 채 옛 데이터를 유지했다.

요약하면, 동기 갱신을 위한 전역 신호는 이미 있었는데 회고 저장 경로 하나만
그 신호를 우회해 컴포넌트-로컬 신호에 연결돼 있었다.

## 해결

회고 저장 콜백을 전역 `refreshKey` 로 통일했다 (이 문서와 같은 PR).

- `Calendar` 에 `onDataChange` 콜백 prop 을 추가하고, `AppShell` 이
  `() => setRefreshKey(k + 1)` 을 넘긴다.
- 회고 모달의 저장 성공 콜백이 `localRefresh` 대신 `onDataChange` 를 호출한다.
- 역할이 사라진 `localRefresh` 로컬 state 는 제거 — 캘린더도 `refreshKey` 를
  이미 구독하므로 캘린더 갱신은 그대로 유지된다.

이제 회고 저장 → `refreshKey` +1 → 캘린더·타임라인이 동시에 재조회된다.

## 재발 방지

- 데이터 변경 후 화면 갱신은 컴포넌트-로컬 신호가 아니라 `AppShell` 의 전역
  `refreshKey` 를 올린다. 한 화면에서 같은 데이터를 그리는 영역이 둘 이상이면
  로컬 신호는 그중 하나만 갱신한다.
- 새 mutation(저장·삭제) UI 를 붙일 때 "이 데이터를 보는 다른 영역이 있나?"
  를 점검하고, 있으면 전역 신호 경로를 쓴다.
